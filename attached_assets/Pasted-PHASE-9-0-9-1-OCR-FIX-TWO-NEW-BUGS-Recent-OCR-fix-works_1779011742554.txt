BUG 1 — TITLES MERGED INTO FOLLOWING SENTENCES
═══════════════════════════════════════════════════════════════

Lines that look like titles or headings (e.g. "Chapter 1", section 
names — short text that doesn't end with punctuation) are being 
joined onto the start of the next sentence with a space, instead of 
being kept as their own paragraph.

Example actual output: "Chapter 1 Once upon a time..."
Should be:
  Chapter 1
  [blank line]
  Once upon a time...

Cause: the sentence-boundary heuristic in cleanText only inserts a 
paragraph break if the previous line ends with .!?…  A title with no 
ending punctuation doesn't trigger a break.

FIX — Add a "looks like a title" detection rule to cleanText:

Between consecutive lines, insert a paragraph break (\n\n instead of 
a space) if EITHER:
  (a) Previous line ends with terminal punctuation .!?…  
      AND next line starts with a capital letter  
      [existing rule]
  
  OR  
  
  (b) Previous line is "title-shaped" — meaning ALL of:
      - Length < 60 characters
      - Does NOT end with terminal punctuation .!?…
      - Next line starts with a capital letter
      - Previous line is significantly shorter than the average 
        line length on the page (e.g. < 70% of average)

Rule (b) catches chapter titles, headings, and section labels 
without falsely triggering on regular sentences that happen to be 
short.

Test cases to verify:
- "Chapter 1\nOnce upon a time..." → should become "Chapter 1\n\nOnce upon a time..."
- "INTRODUCTION\nThe book begins..." → "INTRODUCTION\n\nThe book begins..."
- A short legitimate sentence at the end of a paragraph followed by 
  another sentence on a new line → should NOT trigger rule (b) 
  because line lengths similar
- A short line ending with "." followed by capital → already 
  handled by rule (a), no change

BUG 2 — DEVICE NAME APPEARING IN SCANNED OUTPUT

This is the phone's device name. The OCR plugin reads a captured 
image; it does not read the live camera HUD or system UI. So this 
is NOT coming from the OCR plugin reading something on screen — it
